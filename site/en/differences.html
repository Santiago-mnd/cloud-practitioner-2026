CloudTrail or CloudWatch? Shield or WAF? One phrase to tell each pair apart.

Cloud Concepts 01–07

01

Agility means launching fast; elasticity means adjusting to demand

New resources available in minutes = agility. Scaling up and down with the workload = elasticity.

Where it gets confusing: Both sound like speed, and they can appear together in a launch scenario.

AWS lists six advantages of the cloud. “Increase speed and agility” means getting new resources in minutes so you can experiment more. “Stop guessing capacity” means scaling it up or down based on actual demand: elasticity. High availability answers a different question: whether the service stays online when one part fails.

Benefits

02

Economies of scale and variable expense lower costs in different ways

Pay only for what you use = variable expense. Lower prices because AWS combines many customers’ usage = economies of scale.

Where it gets confusing: Both can mean “it costs less,” so they seem like the same advantage.

Trading fixed expense for variable expense means avoiding an upfront investment in data centers and servers, then paying only when you use them. Economies of scale come from AWS combining the usage of hundreds of thousands of customers. That volume lets AWS charge a lower usage price than a company could obtain on its own.

Cloud economics

03

The six Well-Architected pillars differ in the questions they answer

Working correctly and consistently = reliability. Using the right resources as demand changes = performance efficiency. Energy use or environmental impact = sustainability.

Where it gets confusing: Several pillars sound like “making everything work well.” Turning off unused resources saves both money and energy, so cost optimization and sustainability overlap.

The AWS Well-Architected Tool assesses a workload against the framework’s best practices and recommends improvements.

Which answer fits each situation
Organize the team, operate the workload, and improve it over timeOperational excellence
Protect data, systems, and assetsSecurity
Have the workload perform its function correctly and consistentlyReliability
Use resources efficiently as demand and technology changePerformance efficiency
Deliver business value at the lowest priceCost optimization
Reduce environmental impact, especially energy useSustainability

Well-Architected

04

The AWS CAF has six perspectives and four business outcomes

Business, people, governance, platform, security, and operations = perspectives. Lower risk, better ESG, more revenue, and greater efficiency = outcomes.

Where it gets confusing: The two lists sound similar, and “governance” is both a perspective and part of ESG.

The AWS Cloud Adoption Framework (AWS CAF) groups the capabilities an organization needs to adopt the cloud into six perspectives; each has its own stakeholders. The outcomes are what the transformation delivers to the business: lower risk, better environmental, social, and governance (ESG) performance, more revenue, and greater operational efficiency.

Cloud adoption

05

The seven migration strategies differ in what happens to the application

No changes = rehost. Some adjustments = replatform. Cloud-native redesign = refactor. Different product = repurchase.

Where it gets confusing: Rehost, relocate, and replatform all sound like moving an application to the cloud.

For large migrations, AWS recommends rehost, replatform, or relocate, and saving redesign for after the migration, because refactor is the most complex strategy.

Which answer fits each situation
Move it as-is, without changes (lift and shift)Rehost
Move it with some adjustments to take advantage of the cloud (lift, tinker and shift)Replatform
Redesign it using cloud-native capabilitiesRefactor
Replace it with another product, often software as a service or SaaS (drop and shop)Repurchase
Move many servers to the cloud version of the same platform, without buying hardware or rewritingRelocate
Leave it where it is for nowRetain
Shut it down because it no longer adds valueRetire

Migration

06

With BYOL, you reuse your own license; with license included, AWS charges for it

Already has licenses and wants to reuse them = BYOL.

Where it gets confusing: Either way, the software runs on AWS, so the difference can seem purely financial.

With license included, the service price covers the software license—for example, Oracle Database Standard Edition 2 on Amazon RDS, which also supports BYOL. With BYOL (Bring Your Own License), a company uses licenses it has already purchased. Some licenses are counted by socket or physical core, and Dedicated Hosts let companies use them.

Cloud economics

07

Rightsizing changes instance size; Auto Scaling changes instance count

Oversized instances all the time = rightsizing. Workload rises and falls = Auto Scaling.

Where it gets confusing: Both adjust capacity to match usage and avoid overspending.

Rightsizing selects the instance type and size that fit actual usage at the lowest cost. It takes ongoing review. AWS Compute Optimizer provides recommendations for this. Auto Scaling adds or removes instances as demand changes without resizing them.

Cloud economics

Security and Compliance 08–20

08

AWS secures the cloud; customers secure what they put in it

Facilities, hardware, networking, and virtualization = AWS. Data, identities, configuration, and guest operating system = customer.

Where it gets confusing: “Security OF the cloud” and “security IN the cloud” sound almost identical.

AWS is responsible for security OF the cloud: the hardware, software, networking, and facilities that run its services. Customers are responsible for security IN the cloud: their data, access, configuration, and, depending on the service, operating systems and applications.

Shared responsibility

09

Customer responsibilities change from one service to another

EC2 = the customer patches the operating system. S3 or DynamoDB = AWS operates everything up to the platform.

Where it gets confusing: The shared responsibility model can look like a fixed dividing line, but that line shifts by service.

The more abstract the service, the more layers AWS operates. Data, encryption settings, and AWS Identity and Access Management (IAM) permissions always remain the customer’s responsibility.

Which answer fits each situation
Amazon EC2Customer: guest operating system and its patches, applications, and security group
Amazon RDSAWS: patches, backups, and failure recovery. Customer: data, users, and network access
AWS LambdaAWS: servers, operating system, capacity, and scaling. Customer: code, data, and permissions
Amazon S3 and DynamoDBAWS: infrastructure, operating system, and platform. Customer: data, encryption settings, and permissions

Shared responsibility

10

With shared controls, each party covers its own layer

Patching, configuration, and training = shared controls. Physical and environmental controls = inherited from AWS.

Where it gets confusing: “Shared” can sound like AWS and the customer do the same task together.

AWS handles inherited controls entirely, and customers receive them as they are, such as physical and environmental controls. With shared controls, each party handles its own layer: AWS patches its infrastructure while customers patch their guest operating systems and applications; AWS trains its staff while customers train theirs. Customer-specific controls, such as separating data into security zones, belong entirely to the customer.

Shared responsibility

11

CloudWatch, CloudTrail, and Config answer three different questions

How is it performing? = CloudWatch. Who did what? = CloudTrail. How is it configured, and does it comply? = Config.

Where it gets confusing: All three record something, and the exam guide groups them under the same governance and compliance skill.

A configuration change leaves a trail in the last two: CloudTrail records who made the call, while Config records the resulting configuration if it is recording that resource type.

Which answer fits each situation
Metrics, logs, and alarms for resources and applicationsAmazon CloudWatch
Who took each action in the account, and whenAWS CloudTrail
Resource configuration history and evaluation against rulesAWS Config

Monitoring and auditing

12

Artifact provides AWS reports; Config evaluates your resources

Download an AWS SOC or PCI report = Artifact.

Where it gets confusing: Both come up when a question mentions “compliance.”

AWS Artifact is the portal for downloading AWS compliance documents, including SOC and PCI reports and ISO certifications. You can also accept agreements with AWS there. It helps show an auditor what AWS handles on its side. AWS Config checks whether customer resources comply with rules the customer defines.

Compliance

13

Five security services, five different questions

Vulnerabilities = Inspector. Suspicious activity = GuardDuty. Root cause = Detective. Sensitive data in S3 = Macie. Combined findings = Security Hub.

Where it gets confusing: They all look for security problems, but their names don’t tell you what each one finds.

Inspector checks installed software. GuardDuty analyzes account activity, network, and DNS logs.

Which answer fits each situation
Software vulnerabilities and network exposure in EC2, container images, and LambdaAmazon Inspector
Suspicious or malicious activity in the accountAmazon GuardDuty
Investigate a finding down to its root causeAmazon Detective
Sensitive data, such as personal information, stored in S3Amazon Macie
Bring together findings from multiple services and assess security posture against standardsAWS Security Hub

Protection

14

Shield stops DDoS, WAF filters web requests, and Firewall Manager manages rules

Denial of service = Shield. SQL injection or XSS = WAF. Rules across all accounts = Firewall Manager.

Where it gets confusing: All three are presented as perimeter protection, and WAF and Shield often appear together.

AWS Shield Standard protects against the most common distributed denial-of-service (DDoS) attacks at no additional cost, with no setup required. Shield Advanced is paid and adds protection and specialized help. AWS WAF filters HTTP and HTTPS requests using rules, for example, against SQL injection and cross-site scripting (XSS). AWS Firewall Manager manages those rules centrally across AWS Organizations accounts.

Protection

15

Keys, dedicated HSMs, certificates, and secrets belong to separate services

Encryption keys = KMS. Dedicated HSM = CloudHSM. TLS certificates = ACM. Rotating passwords = Secrets Manager.

Where it gets confusing: They all sound like ways to store something secret.

Other AWS services, such as S3 and EBS, integrate with KMS to encrypt their data using KMS keys.

Which answer fits each situation
Create and control managed encryption keysAWS Key Management Service (KMS)
A dedicated hardware security module (HSM) controlled by the customerAWS CloudHSM
Issue and renew SSL/TLS certificatesAWS Certificate Manager
Store credentials and rotate them automaticallyAWS Secrets Manager

Encryption and secrets

16

Encryption in transit protects data in motion; encryption at rest protects stored data

TLS or HTTPS = in transit. Data stored in S3, EBS, or RDS = at rest.

Where it gets confusing: Both are called encryption, and many services offer both.

Encryption in transit protects data as it moves between systems, using encryption protocols such as TLS. Encryption at rest protects stored data; on AWS, you can use AWS KMS keys for it.

Encryption and secrets

17

An IAM user has long-term credentials; a role is assumed

Temporary credentials or cross-account access = role.

Where it gets confusing: Both can have permission policies, so they may seem like two versions of the same thing.

An IAM user is an identity with long-term credentials: a password for the console or access keys for the command line (CLI) and software development kits (SDK). A role has no long-term credentials; whoever assumes it receives temporary credentials. Roles grant permissions to services, other accounts, or federated identities.

Identity and access

18

IAM, IAM Identity Center, and Cognito serve different people

Employees across multiple accounts = Identity Center. Users of your app = Cognito.

Where it gets confusing: All three authenticate users.

IAM Identity Center was previously called AWS Single Sign-On, and that name still appears in study materials.

Which answer fits each situation
Identities and permissions within an AWS accountAWS IAM
Employee single sign-on across multiple accounts and applicationsAWS IAM Identity Center
Sign-up and sign-in for users of your web and mobile appsAmazon Cognito

Identity and access

19

An SCP sets the ceiling; an IAM policy grants permission

Limit what users and roles in member accounts can do = SCP.

Where it gets confusing: Both use JSON to allow or deny actions.

AWS Organizations service control policies (SCPs) set the maximum permissions for users and roles in member accounts, including their root users. They grant no permissions on their own and do not affect the management account. To take an action, an IAM policy must allow it, as must the SCPs at every level above the account: one level that does not allow it is enough to block it.

Identity and access

20

Save the root user for a few specific tasks

In a standalone account, changing the root email or password, or closing the account = root user.

Where it gets confusing: The root user can do everything, so it seems like the natural choice for administration.

AWS recommends keeping the root user out of day-to-day work, protecting it with multifactor authentication (MFA), and reserving it for tasks that require it. These include restoring permissions to an IAM administrator who removed their own. In an account outside AWS Organizations, they also include changing the root user's email, password, and access keys, and closing the account.

Identity and access

Cloud Technology and Services 21–37

21

AWS calls the private cloud “on-premises”

Everything on AWS = cloud. AWS connected to your own data center = hybrid. Everything in your own data center = on-premises.

Where it gets confusing: If you studied another syllabus, you may look for “public, private, and hybrid” and not find those terms among the options.

The CLF-C02 guide names three deployment models: cloud, hybrid, and on-premises. In the cloud model, the application runs entirely in the cloud. Hybrid connects cloud resources to resources outside it. On-premises means the infrastructure is in your own data center; AWS sometimes calls this a private cloud.

Deployment

22

Use the console for one-off tasks; put repeatable work in code

One-off task = console. Repeatable or automated process = CLI, SDK, or infrastructure as code.

Where it gets confusing: You can do everything from the console, so it seems like the safe answer.

The AWS Management Console provides a visual interface for one-off tasks. The CLI, SDKs, and APIs—the interfaces programs use—let you automate tasks. With infrastructure as code, such as AWS CloudFormation, you describe an environment in templates and create it the same way each time.

Deployment

23

Region, Availability Zone, and edge location are three different levels

Data center failure = multiple AZs. Regional disaster, latency, or data sovereignty = multiple Regions. Content close to users = edge location.

Where it gets confusing: All three are AWS locations, and a high-availability scenario may seem to call for more Regions.

A Region is a physical location with multiple Availability Zones (AZs), isolated from other Regions. Each AZ contains one or more data centers with redundant power, networking, and connectivity; AZs do not share single points of failure. Edge locations bring content closer to users through Amazon CloudFront.

Global infrastructure

24

Choose an instance family by the resource your workload uses most

CPU-intensive = compute optimized. Large datasets in memory = memory optimized. Heavy local reads and writes = storage optimized.

Where it gets confusing: They are all EC2 virtual machines, and the letters in each family are not obvious at first glance.

EC2 groups instance types into families based on the resource they optimize.

Which answer fits each situation
Balance of compute, memory, and networkingGeneral purpose
Batch jobs, transcoding, high-performance web servers, high-performance computing (HPC)Compute optimized
Large datasets processed in memoryMemory optimized
Heavy sequential reads and writes on very large local datasetsStorage optimized
Hardware accelerators, such as GPUsAccelerated computing

Compute

25

ECS, EKS, Fargate, and Lambda handle different layers

Kubernetes = EKS. Containers without managing servers = Fargate. Event-driven code, up to 15 minutes = Lambda.

Where it gets confusing: All four run code without you handling hardware, and Fargate works with both ECS and EKS.

ECS and EKS orchestrate containers: ECS is AWS's orchestrator, while EKS is managed Kubernetes. Fargate is the serverless engine that runs those containers without managing EC2 instances. Lambda runs functions in response to events, with a maximum of 15 minutes per execution.

Compute

26

The load balancer distributes traffic; Auto Scaling decides how many instances run

Distribute requests across healthy instances = Elastic Load Balancing. Add or remove instances = Auto Scaling.

Where it gets confusing: They appear together in architecture diagrams, so they can look like one service.

Elastic Load Balancing distributes incoming traffic across multiple targets and stops sending it to unhealthy ones. Amazon EC2 Auto Scaling maintains the number of instances and adjusts it based on demand; that is what provides elasticity.

Compute

27

Each data model has a managed database option

Relational = RDS or Aurora. Serverless NoSQL = DynamoDB. In-memory cache = ElastiCache. Analytics data warehouse = Redshift.

Where it gets confusing: They all store data, and AWS manages all of them.

First, choose the data model. Then decide whether AWS should manage the database or you should install it on EC2 to control the database engine and operating system.

Which answer fits each situation
Managed relational database with several enginesAmazon RDS
AWS relational database compatible with MySQL and PostgreSQLAmazon Aurora
Serverless key-value and document NoSQL databaseAmazon DynamoDB
Document database compatible with MongoDBAmazon DocumentDB
GraphsAmazon Neptune
In-memory cacheAmazon ElastiCache
Analytics data warehouseAmazon Redshift
Full control of the database engine and operating systemDatabase installed on EC2

Databases

28

DMS moves the data; SCT converts the schema

Different source and target engines = SCT for the schema and DMS for the data.

Where it gets confusing: Both tools come up in database migrations.

AWS Database Migration Service copies data from one database to another: it can perform a one-time migration or replicate ongoing changes to keep the source and target in sync. AWS Schema Conversion Tool converts the schema and database code when the engine changes, for example, from Oracle to Aurora PostgreSQL.

Databases

29

A security group protects the instance; a network ACL protects the subnet

Deny rule or subnet level = network ACL. Allow only, at the instance level = security group.

Where it gets confusing: Both filter traffic with port and address rules inside an AWS virtual private cloud (VPC).

A security group is associated with instances, supports only allow rules, and is stateful: if a connection is allowed in, its response can leave without another rule. A network access control list (ACL) is associated with a subnet, supports both allow and deny rules, and is stateless: inbound and outbound traffic must each be allowed separately.

Networking

30

To connect networks to AWS, choose based on what needs to connect

Dedicated physical link = Direct Connect. Encrypted tunnel over the internet = Site-to-Site VPN. People on their own devices = Client VPN.

Where it gets confusing: All four connect something to a VPC.

Direct Connect avoids the internet. Site-to-Site VPN travels over the internet through an encrypted IPsec tunnel.

Which answer fits each situation
Dedicated, private physical connection from a data centerAWS Direct Connect
Encrypted IPsec tunnel over the internet between a network and the VPCAWS Site-to-Site VPN
Access for people using their own devicesAWS Client VPN
A hub connecting many VPCs and on-premises networksAWS Transit Gateway

Networking

31

CloudFront delivers web content, Global Accelerator speeds up TCP and UDP, and Route 53 resolves names

Cached web content near users = CloudFront. Static IP addresses or non-HTTP traffic = Global Accelerator. DNS = Route 53.

Where it gets confusing: All three use the AWS global network and improve what users experience.

Amazon CloudFront is a content delivery network that caches copies at edge locations and also speeds up dynamic content. AWS Global Accelerator provides static IP addresses. It receives TCP or UDP packets at an edge location and carries them to the Region over the AWS network. Amazon Route 53 is the DNS service, the system that translates domain names into addresses: it registers domains, routes traffic, and checks the health of destinations.

Networking

32

Block, file, or object: the first storage question

Disk for an instance = EBS. Shared folder for Linux instances = EFS; for Windows instances = FSx for Windows File Server. Objects accessed through an API = S3.

Where it gets confusing: S3, EBS, and EFS all store data, and each has an S in its name.

AWS Backup and Elastic Disaster Recovery handle backups and recovery. Storage Gateway also supports backup and archiving from on-premises environments.

Which answer fits each situation
Persistent block storage for an instanceAmazon EBS
Temporary block storage, lost when the instance stops or terminatesInstance store

Third-party file systems: Windows File Server, Lustre, NetApp ONTAP, OpenZFSAmazon FSx
Objects accessible through an APIAmazon S3
Cached local access to cloud storageAWS Storage Gateway
Centralized backups with policiesAWS Backup
Continuous replication to recover servers after a disasterAWS Elastic Disaster Recovery

Storage

33

Choose an S3 storage class by access frequency and how long retrieval can take

Unpredictable access = Intelligent-Tiering. Data you can recreate = One Zone-IA. Can wait hours = Glacier Flexible Retrieval or Deep Archive.

Where it gets confusing: Every class stores the same object; price, Availability Zones, and retrieval time vary.

Lifecycle policies move objects between classes using fixed rules, such as an object's age. Intelligent-Tiering moves them only between its own access tiers, within the same class, based on actual access.

Frequent accessS3 Standard
Unknown or changing access patternsS3 Intelligent-Tiering
Infrequent access, data you cannot recreateS3 Standard-IA
Infrequent access, data you can recreate; a single AZS3 One Zone-IA
Archive retrieved in millisecondsS3 Glacier Instant Retrieval
Archive retrieved in minutes or hoursS3 Glacier Flexible Retrieval

Storage

Querying, transforming, processing, streaming, and visualizing use different services

SQL queries on S3 data = Athena. Serverless ETL = Glue. Real-time data = Kinesis. Dashboards = Quick Sight.

Where it gets confusing: They all work with data for analysis, and a real architecture may use them together.

For example, Kinesis can receive the data, Glue can transform it, Athena can query it, and Quick Sight can display it on a dashboard.

AI and machine learning

SNS delivers a message to its subscribers as soon as it arrives. In SQS, the message waits in the queue until a consumer requests it.

Billing, Pricing, and Support 38–45

38

Your EC2 purchasing option depends on your commitment and tolerance for interruptions

Can be interrupted = Spot Instances. Steady use for 1 or 3 years = Savings Plans or Reserved Instances. Per-socket or per-core license = Dedicated Hosts.

Where it gets confusing: Several options offer discounts, and several use the word “reserve.”

Capacity Reservations guarantee capacity but, on their own, are billed at On-Demand rates; combine them with Savings Plans or regional Reserved Instances for a discount.

Which answer fits each situation
No commitment, pay for what you useOn-Demand Instances
Spare capacity at a steep discount that AWS can reclaimSpot Instances
Commitment to hourly spending for 1 or 3 years; Compute Savings Plans work across instance families, Regions, and servicesSavings Plans
Commitment to an instance configuration for 1 or 3 yearsReserved Instances
An entire physical server, with visibility into sockets and coresDedicated Hosts
Hardware isolated for your account, without control of the serverDedicated Instances
Guarantee capacity in an AZCapacity Reservations

Pricing

39

Savings Plans commit you to spending; Reserved Instances commit you to a configuration

Discount that also covers Fargate and Lambda = Compute Savings Plans.

Where it gets confusing: Both offer a discount in exchange for a 1- or 3-year commitment.

With Savings Plans, you commit to spending a set amount per hour. Compute Savings Plans apply regardless of instance family, size, operating system, tenancy, or Region; they also cover Fargate and Lambda. A Reserved Instance commits you to a configuration: Standard offers a larger discount, while Convertible lets you exchange it for another configuration. In AWS Organizations, discounts are shared across accounts under consolidated billing unless sharing is turned off.

Pricing

40

Data transfer in from the internet is free; data transfer out costs money

Out to the internet = charged. In = generally free.

Where it gets confusing: It seems reasonable to expect data transfer to cost the same in both directions.

Data transfer in from the internet to AWS is free. Data transfer out to the internet is charged; the more you transfer, the less each GB costs. Within a Region, some services do not charge for traffic, but data transfer between Availability Zones is charged in both directions. Transferring data to another Region also incurs charges.

Pricing

41

Estimate, analyze, alert, and itemize: a cost tool for each job

Before you build = AWS Pricing Calculator. Past spending and forecasts = Cost Explorer. Alert at a threshold = Budgets. Most detail = CUR.

Where it gets confusing: All four deal with costs and sit together in the billing console.

AWS Budgets alerts you when actual or forecasted spending crosses a threshold. Budget actions can also apply an IAM policy or an SCP, or stop EC2 or RDS instances. Those actions can run automatically or after approval.

Which answer fits each situation
Estimate costs before you buildAWS Pricing Calculator
View and analyze spending, including forecastsAWS Cost Explorer
Get an alert when actual or forecasted spending crosses a thresholdAWS Budgets
The most detailed cost and usage data, delivered to S3AWS Cost and Usage Report (CUR)
Compute sizing recommendations based on usageAWS Compute Optimizer

Costs

42

A tag will not appear in cost reports until you activate it

Costs by project or department = activated cost allocation tags.

Where it gets confusing: You tag a resource and expect it to show up in the cost report right away.

There are AWS-generated tags, such as createdBy, and user-defined tags. You activate both in the Billing and Cost Management console; only then does AWS use them to organize costs in the allocation report.

Costs

43

Organizations groups accounts; Control Tower sets up the landing zone

Consolidated billing and SCPs = Organizations. Ready-to-use multi-account environment with controls = Control Tower.

Where it gets confusing: Both manage multiple accounts.

AWS Organizations groups accounts into organizational units, consolidates billing, and applies SCPs. AWS Control Tower uses Organizations to set up a landing zone with preconfigured controls.

Accounts

44

The exam’s Support plans differ by TAM access and response time

Designated TAM = Enterprise. TAM team = Enterprise On-Ramp. 24/7 phone support = Business and above. Business-hours web support only = Developer.

Where it gets confusing: Paid plans share many features, and “Enterprise On-Ramp” sounds like a step below Business.

The CLF-C02 guide names Developer, Business, Enterprise On-Ramp, and Enterprise; the exam follows that guide. AWS will discontinue Developer, Business, and Enterprise On-Ramp on January 1, 2027; it currently offers Business Support+, Enterprise Support, and Unified Operations. Basic is free and includes customer service, core Trusted Advisor checks, and AWS Health.

Which answer fits each situation
Experimenting or testing; business-hours web supportDeveloper
Minimum recommended for production; 24/7 phone, web, and chat support; all Trusted Advisor checksBusiness
Critical workloads; a team of technical account managers (TAMs); under 30 minutes for a critical system outageEnterprise On-Ramp
Critical workloads; designated TAM; under 15 minutes for a critical system outageEnterprise

Support

Know where to turn at AWS for each need

Report abuse from AWS resources = Trust & Safety. AWS consulting = Professional Services. Third-party software = Marketplace.

Where it gets confusing: Several options sound like ways to ask AWS for help.

Trust & Safety handles abuse originating from AWS resources. For a technical issue with your own account, contact AWS Support.
